# ДЗ-7. Промпт-генератор тестовой документации + оценка через Ollama

Генерирует промпты для LLM — по одному на каждый из 4
типов тестовой документации: test case, checklist, test plan, QA report.
Промпты строятся по шаблону Роль → Контекст → Техника → Формат → Ограничения
на основе требования из `input/requirement.md`.

Качество проверяется в двух независимых плоскостях через LLM-судью на Ollama:
- **качество сгенерированного документа** (`evaluator.py`, запускается из `run.py`) —
  по 9 критериям: 4 обязательных по условию ДЗ (читаемость, контекстность,
  чёткость целей, покрытие сценариев) + недвусмысленность + 4 из
  характеристик хорошего требования, которые не дублируют предыдущие
  (атомарность, единичность, непротиворечивость, корректность);
- **качество самого требования** на входе (`requirement_quality.py`) — по 11
  характеристикам хорошего требования (завершённость, атомарность,
  единичность, непротиворечивость, выполнимость, нужность, актуальность,
  прослеживаемость, модифицируемость, корректность, проверяемость; источник —
  «Тестирование ПО. Базовый курс», © EPAM Systems).

## Стек

Python 3, Docker, Ollama (`qwen2.5:7b`), библиотека `openai` (OpenAI-совместимый клиент к Ollama).

## Структура

- `input/requirement.md` — требование (форма регистрации)
- `prompt_generator.py` — строит промпты по 4 типам документов
- `evaluator.py` — прогоняет промпт через Ollama и оценивает результат LLM-судьёй
- `requirement_quality.py` — отдельно оценивает качество самого требования (не документа) по характеристикам хорошего требования
- `run.py` — точка входа: генерирует и оценивает все 4 типа, пишет результаты
- `analyze_runs.py` — считает разброс оценок между всеми накопленными прогонами
- `dev/check_step4.py` — вспомогательный скрипт для ручной проверки одного типа документа при разработке, не часть сдачи
- `results/latest/` — результаты последнего прогона (4 типа документов + качество требования)
- `results/history/NN-progon/` — архив каждого прогона
- `results/stability_report.md` — таблица разброса оценок по прогонам

## Локальный запуск

1. Поднять Ollama в Docker:
   ```
   docker compose up -d
   docker exec ollama-hm7 ollama pull qwen2.5:7b
   ```
2. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
3. Сгенерировать и оценить документы (все 4 типа):
   ```
   python run.py
   ```
   Результат — `results/latest/*_results.md` (последний прогон) + копия в
   `results/history/NN-progon/` (архив).
4. Оценить качество самого требования:
   ```
   python requirement_quality.py
   ```
   Результат — `results/latest/requirement_quality_results.md`.
5. (опционально) После нескольких запусков `run.py` — посчитать разброс
   оценок между прогонами:
   ```
   python analyze_runs.py
   ```
   Результат — `results/stability_report.md`.
