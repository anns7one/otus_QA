# Результат: test_case

## Промпт
```
Ты senior QA-инженер.

Контекст (требование):
# REQ-01 - Форма регистрации

Форма принимает поля: Имя, E-mail, Телефон, Пароль, согласие с политикой
конфиденциальности, кнопку «Зарегистрироваться», кнопку перехода к авторизации, кнопку перехода к восстановлению пароля.

- **Имя.** Обязательно для заполнения. Принимает на вход только буквы до 50 символов.
- **E-mail.** Обязательно для заполнения. Валидация: содержит символ `@`,
  значение введено латиницей или цифрами. Проходит проверку на уникальность: если в базе уже есть пользователь с таким email — ошибка «Пользователь с таким email уже существует, авторизуйтесь на сайте».
- **Телефон.** Обязательно для заполнения. Маска: `+7(...)...-..-..`.
  Проходит проверку на уникальность: если в базе уже есть пользователь с
  таким номером — ошибка «Пользователь с таким номером телефона уже
  существует, авторизуйтесь на сайте».
- **Пароль.** Обязательно для заполнения.От 8 до 64 символов, минимум одна цифра и одна заглавная буква.Допустимые символы: цифры, латинские буквы,знаки препинания.
- **Согласие с политикой конфиденциальности.** Обязательный чекбокс по умолчанию должен быть активен

## Поведение

- Если незаполненных обязательных полей ≥ 1 - регистрация не происходит, появляется текст «Заполните обязательные поля» (или подсветка пустых
  полей, в зависимости от дизайна).
- Если все обязательные поля заполнены и валидны - пользователь
  регистрируется.
- После успешной регистрации - поп-ап с подтверждением, пользователь
  остаётся на той же странице, где был открыт поп-ап регистрации.
- Система авторизует пользователя сразу после успешной регистрации.


Техника: Применяй классы эквивалентности и анализ граничных значений.

Формат: Верни РОВНО 3 тест-кейса: один позитивный, один граничный, один негативный. Для каждого — в виде:
ID: ...
Название: ...
Предусловия: ...
Шаги: 1. ... 2. ...
Ожидаемый результат: ...
Приоритет: High/Medium/Low

Ограничения: Пиши на русском. Не придумывай требований, которых нет в тексте выше.
```

## Сгенерированный документ
```
ID: TC_01
Название: Успешная регистрация пользователя с корректными данными
Предусловия: Пользователь находится на странице регистрации.
Шаги:
1. Ввести имя "Иван" (5 символов).
2. Ввести email "ivan@example.com".
3. Ввести телефон "+7(900)123-45-67".
4. Ввести пароль "Qwerty123!".
5. Активировать чекбокс согласия с политикой конфиденциальности.
6. Нажать кнопку "Зарегистрироваться".
Ожидаемый результат: Появляется поп-ап с сообщением об успешной регистрации, пользователь остается на странице регистрации.
Приоритет: High

ID: TC_02
Название: Регистрация пользователя с граничным значением пароля
Предусловия: Пользователь находится на странице регистрации.
Шаги:
1. Ввести имя "Петр" (5 символов).
2. Ввести email "petr@example.com".
3. Ввести телефон "+7(900)123-45-67".
4. Ввести пароль "Qwerty123". (8 символов, без цифры и заглавной буквы)
5. Активировать чекбокс согласия с политикой конфиденциальности.
6. Нажать кнопку "Зарегистрироваться".
Ожидаемый результат: Появляется сообщение об ошибке, указывающее на то, что пароль должен содержать как минимум одну цифру и одну заглавную букву.
Приоритет: High

ID: TC_03
Название: Неудачная регистрация пользователя с пустым полем имени
Предусловия: Пользователь находится на странице регистрации.
Шаги:
1. Оставить поле имени пустым.
2. Ввести email "invalid@example.com".
3. Ввести телефон "+7(900)123-45-67".
4. Ввести пароль "Qwerty123!".
5. Активировать чекбокс согласия с политикой конфиденциальности.
6. Нажать кнопку "Зарегистрироваться".
Ожидаемый результат: Появляется сообщение об ошибке, указывающее на то, что поле имени обязательно для заполнения и должно содержать только буквы до 50 символов.
Приоритет: High
```

## Оценка
| Критерий | Балл | Комментарий |
|---|---|---|
| readability | 4 | Структура документа понятна, но формулировки шагов могут быть более чёткими и последовательными. |
| contextuality | 5 | Документ точно соответствует требованиям и не содержит лишних условий или предположений. |
| goal_clarity | 4 | Цели проверки ясны, но можно было бы более детально описать, что именно должно быть проверено в каждом тесте. |
| scenario_coverage | 4 | Покрыты позитивные и негативные случаи, но не указаны граничные значения для полей. |
| unambiguity | 5 | Формулировки четкие и не подвержены двумя трактовкам. |
