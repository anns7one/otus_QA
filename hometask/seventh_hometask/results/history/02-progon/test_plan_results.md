# REQ-01 - Форма регистрации

Форма принимает поля: Имя, E-mail, Телефон, Пароль, согласие с политикой
конфиденциальности, кнопку «Зарегистрироваться», кнопку перехода к авторизации, кнопку перехода к восстановлению пароля.

- **Имя.** Обязательно для заполнения. Принимает на вход только буквы до 50 символов.
- **E-mail.** Обязательно для заполнения. Валидация: содержит символ `@`,
  значение введено латиницей или цифрами. Проходит проверку на уникальность: если в базе уже есть пользователь с таким email — ошибка «Пользователь с таким email уже существует, авторизуйтесь на сайте».
- **Телефон.** Обязательно для заполнения. Маска: `+7(...)...-..-..`.
  Проходит проверку на уникальность: если в базе уже есть пользователь с
  таким номером — ошибка «Пользователь с таким номером телефона уже
  существует, авторизуйтесь на сайте».
- **Пароль.** Обязательно для заполнения.От 8 до 64 символов, минимум одна цифра и одна заглавная буква.Допустимые символы: цифры, латинские буквы,знаки препинания.
- **Согласие с политикой конфиденциальности.** Обязательный чекбокс по умолчанию должен быть активен

## Поведение

- Если незаполненных обязательных полей ≥ 1 - регистрация не происходит, появляется текст «Заполните обязательные поля» (или подсветка пустых
  полей, в зависимости от дизайна).
- Если все обязательные поля заполнены и валидны - пользователь
  регистрируется.
- После успешной регистрации - поп-ап с подтверждением, пользователь
  остаётся на той же странице, где был открыт поп-ап регистрации.
- Система авторизует пользователя сразу после успешной регистрации.


Техника: Структурируй план по ISO/IEC/IEEE 29119-3: объём тестирования, подход/стратегия, критерии входа/выхода, риски, ресурсы.

Формат: Верни тест-план с разделами: Объём, Подход, Критерии входа, Критерии выхода, Риски, Ресурсы.

Ограничения: Пиши на русском. Не придумывай требований, которых нет в тексте выше.

## Сгенерированный документ
```
### Тест-план

#### Объём тестирования

Тестирование будет охватывать все функциональные требования к форме регистрации, включая проверку обязательных полей, валидацию данных и поведение системы после успешной регистрации.

#### Подход/стратегия

Для тестирования формы регистрации будет использована комбинированная стратегия:

1. **Тестирование функциональности:** Проверка всех функций формы регистрации.
2. **Валидация данных:** Тестирование ввода и валидации данных для каждого поля.
3. **Проверка ошибок и уведомлений:** Убедиться, что система корректно отображает сообщения об ошибках и подсветку полей.
4. **Тестирование сценариев использования:** Проверка различных сценариев регистрации пользователя.

#### Критерии входа

- Все требования к форме регистрации определены и документированы.
- Система доступна для тестирования.
- Участники команды имеют необходимые права доступа и инструменты для тестирования.

#### Критерии выхода

- Все функциональные требования формы регистрации успешно протестированы.
- Отсутствуют критические баги, которые влияют на работу системы.
- Пользовательская документация и отчеты о тестировании подготовлены.
- Система готова к внедрению.

#### Риски

1. **Неправильная валидация данных:** Ошибки в валидации могут привести к неправильной регистрации или авторизации пользователей.
2. **Проблемы с уникальностью данных:** Возможны конфликты при попытках регистрации пользователями с одинаковыми email-адресами и номерами телефонов.
3. **Отсутствие подтверждения регистрации:** Пользователи могут не получить уведомления о успешной регистрации, что может привести к недовольству.

#### Ресурсы

1. **Личный состав:**
   - Тестировщики
   - Разработчики для совместной работы и устранения багов
   - Дизайнеры для проверки визуального оформления сообщений об ошибках

2. **Инструменты:**
   - Автоматизация тестирования (если применимо)
   - Инструменты для отслеживания багов и управления задачами
   - Средства для сбора статистики и анализа результатов тестирования

3. **Документация:**
   - Тест-план
   - Тест-кейсы
   - Отчеты о тестировании

4. **Время:** 
   - Определенное количество времени для планирования, выполнения и отчета по результатам тестирования.

Тестирование формы регистрации будет проводиться с учетом всех указанных критериев и рисков, чтобы обеспечить высокое качество продукта.
```
