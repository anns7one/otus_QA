# Результат: checklist

## Промпт
```
Ты QA-инженер.

Контекст (требование):
# REQ-01 - Форма регистрации

Форма принимает поля: Имя, E-mail, Телефон, Пароль, согласие с политикой
конфиденциальности, кнопку «Зарегистрироваться», кнопку перехода к авторизации, кнопку перехода к восстановлению пароля.

- **Имя.** Обязательно для заполнения. Принимает на вход только буквы до 50 символов.
- **E-mail.** Обязательно для заполнения. Валидация: содержит символ `@`,
  значение введено латиницей или цифрами. Проходит проверку на уникальность: если в базе уже есть пользователь с таким email — ошибка «Пользователь с таким email уже существует, авторизуйтесь на сайте».
- **Телефон.** Обязательно для заполнения. Маска: `+7(...)...-..-..`.
  Проходит проверку на уникальность: если в базе уже есть пользователь с
  таким номером — ошибка «Пользователь с таким номером телефона уже
  существует, авторизуйтесь на сайте».
- **Пароль.** Обязательно для заполнения.От 8 до 64 символов, минимум одна цифра и одна заглавная буква.Допустимые символы: цифры, латинские буквы,знаки препинания.
- **Согласие с политикой конфиденциальности.** Обязательный чекбокс по умолчанию должен быть активен

## Поведение

- Если незаполненных обязательных полей ≥ 1 - регистрация не происходит, появляется текст «Заполните обязательные поля» (или подсветка пустых
  полей, в зависимости от дизайна).
- Если все обязательные поля заполнены и валидны - пользователь
  регистрируется.
- После успешной регистрации - поп-ап с подтверждением, пользователь
  остаётся на той же странице, где был открыт поп-ап регистрации.
- Система авторизует пользователя сразу после успешной регистрации.


Техника: Составь список проверок без шагов выполнения, включая позитивные и негативные случаи.

Формат: Верни маркированный список пунктов проверки, каждый пункт — одна строка.

Ограничения: Пиши на русском. Не более 15 пунктов. Не придумывай требований, которых нет в тексте выше.
```

## Сгенерированный документ
```
- Проверка заполнения обязательных полей без ввода данных.
- Проверка правильности введенного имени (только буквы, до 50 символов).
- Проверка валидации e-mail (содержит символ @, латиница или цифры).
- Проверка уникальности e-mail при регистрации.
- Проверка уникальности номера телефона (+7(...)...-..-..).
- Проверка правильности введенного пароля (8-64 символов, минимум одна цифра и одна заглавная буква).
- Проверка активности чекбокса согласия с политикой конфиденциальности.
- Проверка появления сообщения о заполнении обязательных полей при незаполненных данных.
- Проверка успешной регистрации при корректном вводе всех данных.
- Проверка отображения поп-апа после успешной регистрации.
- Проверка автоматической авторизации пользователя после регистрации.
- Проверка валидации имени с использованием русских букв.
- Проверка валидации пароля без использования цифры или заглавной буквы.
- Проверка валидации e-mail при вводе кириллицы вместо латиницы.
- Проверка валидации номера телефона с некорректной маской.
```

## Оценка
| Критерий | Балл | Комментарий |
|---|---|---|
| readability | 4 | Структура документа понятна, но формулировки некоторых пунктов могут быть улучшены для большей читаемости. |
| contextuality | 5 | Документ точно отражает требование и не содержит лишних условий или неверных сведений. |
| goal_clarity | 4 | Цели проверки четко определены, но некоторые пункты могут быть более подробно описаны для уточнения целей тестирования. |
| scenario_coverage | 3 | Проверяются позитивные и негативные сценарии, но не все граничные случаи учтены (например, проверка на русские буквы в имени или кириллицу в e-mail). |
| unambiguity | 4 | Формулировки большей частью недвусмысленны, но некоторые термины могут быть более точно определены для исключения двоякого толкования. |
