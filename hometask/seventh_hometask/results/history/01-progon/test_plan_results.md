# REQ-01 - Форма регистрации

Форма принимает поля: Имя, E-mail, Телефон, Пароль, согласие с политикой
конфиденциальности, кнопку «Зарегистрироваться», кнопку перехода к авторизации, кнопку перехода к восстановлению пароля.

- **Имя.** Обязательно для заполнения. Принимает на вход только буквы до 50 символов.
- **E-mail.** Обязательно для заполнения. Валидация: содержит символ `@`,
  значение введено латиницей или цифрами. Проходит проверку на уникальность: если в базе уже есть пользователь с таким email — ошибка «Пользователь с таким email уже существует, авторизуйтесь на сайте».
- **Телефон.** Обязательно для заполнения. Маска: `+7(...)...-..-..`.
  Проходит проверку на уникальность: если в базе уже есть пользователь с
  таким номером — ошибка «Пользователь с таким номером телефона уже
  существует, авторизуйтесь на сайте».
- **Пароль.** Обязательно для заполнения.От 8 до 64 символов, минимум одна цифра и одна заглавная буква.Допустимые символы: цифры, латинские буквы,знаки препинания.
- **Согласие с политикой конфиденциальности.** Обязательный чекбокс по умолчанию должен быть активен

## Поведение

- Если незаполненных обязательных полей ≥ 1 - регистрация не происходит, появляется текст «Заполните обязательные поля» (или подсветка пустых
  полей, в зависимости от дизайна).
- Если все обязательные поля заполнены и валидны - пользователь
  регистрируется.
- После успешной регистрации - поп-ап с подтверждением, пользователь
  остаётся на той же странице, где был открыт поп-ап регистрации.
- Система авторизует пользователя сразу после успешной регистрации.

## Сгенерированный документ
```
### Тест-план

#### Объём тестирования

Тестирование будет охватывать все функциональные требования формы регистрации, включая проверку всех полей и их валидацию, а также поведение системы при успешной регистрации пользователя.

#### Подход/стратегия

Подход к тестированию будет основан на методологии черного ящика с дополнительными проверками белого ящика. Тестирование будет проводиться на различных устройствах и браузерах, чтобы убедиться в работоспособности формы регистрации во всех возможных сценариях.

#### Критерии входа

- Все требования к полям формы регистрации определены.
- Система имеет возможность ввода и проверки данных пользователей.
- Существует механизм уникальности email и номера телефона.
- Пользовательская интерфейс (UI) доступна для тестирования.

#### Критерии выхода

- Все поля формы регистрации успешно прошли тестирование по требованиям.
- Валидация полей работает корректно.
- Система правильно реагирует на уникальность email и номера телефона.
- Поп-ап с подтверждением регистрации отображается после успешной регистрации.
- Пользователь автоматически авторизуется после регистрации.

#### Риски

1. **Ошибка валидации полей**: Неправильная реализация валидации может привести к неверному принятию или отказу в регистрации пользователя.
2. **Проблемы с уникальностью данных**: Ошибки при проверке уникальности email и номера телефона могут привести к нежелательным результатам.
3. **Поп-ап не отображается**: Неправильная реализация поп-апа может привести к недостоверной информации для пользователя после успешной регистрации.
4. **Авторизация не происходит**: После успешной регистрации пользователь может остаться без авторизации.

#### Ресурсы

1. **Тестировщики**: Не менее 2 тестировщиков для проведения функционального тестирования.
2. **Инструменты тестирования**: Автоматизированные инструменты для ввода данных и проверки результатов (например, Selenium).
3. **Браузеры и устройства**: Проверка на различных браузерах (Chrome, Firefox, Safari) и мобильных устройствах.
4. **Документация**: Тест-кейсы, требования, логи тестирования.

---

Этот план тестирования поможет обеспечить полное покрытие всех требований к форме регистрации и убедиться в ее корректной работе.
```
