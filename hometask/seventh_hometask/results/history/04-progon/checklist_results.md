# Результат: checklist

## Промпт
```
Ты QA-инженер.

Контекст (требование):
# REQ-01 - Форма регистрации

Форма принимает поля: Имя, E-mail, Телефон, Пароль, согласие с политикой
конфиденциальности, кнопку «Зарегистрироваться», кнопку перехода к авторизации, кнопку перехода к восстановлению пароля.

- **Имя.** Обязательно для заполнения. Принимает на вход только буквы до 50 символов.
- **E-mail.** Обязательно для заполнения. Валидация: содержит символ `@`,
  значение введено латиницей или цифрами. Проходит проверку на уникальность: если в базе уже есть пользователь с таким email — ошибка «Пользователь с таким email уже существует, авторизуйтесь на сайте».
- **Телефон.** Обязательно для заполнения. Маска: `+7(...)...-..-..`.
  Проходит проверку на уникальность: если в базе уже есть пользователь с
  таким номером — ошибка «Пользователь с таким номером телефона уже
  существует, авторизуйтесь на сайте».
- **Пароль.** Обязательно для заполнения.От 8 до 64 символов, минимум одна цифра и одна заглавная буква.Допустимые символы: цифры, латинские буквы,знаки препинания.
- **Согласие с политикой конфиденциальности.** Обязательный чекбокс по умолчанию должен быть активен

## Поведение

- Если незаполненных обязательных полей ≥ 1 - регистрация не происходит, появляется текст «Заполните обязательные поля» (или подсветка пустых
  полей, в зависимости от дизайна).
- Если все обязательные поля заполнены и валидны - пользователь
  регистрируется.
- После успешной регистрации - поп-ап с подтверждением, пользователь
  остаётся на той же странице, где был открыт поп-ап регистрации.
- Система авторизует пользователя сразу после успешной регистрации.


Техника: Составь список проверок без шагов выполнения, включая позитивные и негативные случаи.

Формат: Верни маркированный список пунктов проверки, каждый пункт — одна строка.

Ограничения: Пиши на русском. Не более 15 пунктов. Не придумывай требований, которых нет в тексте выше.
```

## Сгенерированный документ
```
- Проверка заполнения обязательных полей без ввода данных.
- Проверка ввода имени до 50 символов.
- Проверка ввода имени с использованием только букв.
- Проверка ввода E-mail с символом @ и латиницей/цифрами.
- Проверка уникальности E-mail при регистрации.
- Проверка ввода телефона в формате +7(...)...-..-..
- Проверка уникальности номера телефона при регистрации.
- Проверка ввода пароля от 8 до 64 символов с минимум одной цифрой и заглавной буквой.
- Проверка состояния чекбокса согласия с политикой конфиденциальности по умолчанию.
- Проверка успешной регистрации при заполнении всех обязательных полей.
- Проверка отображения сообщения об ошибке «Заполните обязательные поля» при незаполненных обязательных полях.
- Проверка отображения сообщения об ошибке «Пользователь с таким email уже существует, авторизуйтесь на сайте» при попытке регистрации с существующим E-mail.
- Проверка отображения сообщения об ошибке «Пользователь с таким номером телефона уже существует, авторизуйтесь на сайте» при попытке регистрации с существующим телефоном.
- Проверка отображения поп-апа с подтверждением после успешной регистрации.
```

## Оценка
| Критерий | Балл | Комментарий |
|---|---|---|
| readability | 4 | Структура документа понятна, язык простой и лаконичный, но отсутствует разделение на заголовки для улучшения читаемости. |
| contextuality | 5 | Документ точно соответствует требованию без добавления лишних условий или отклонений. |
| goal_clarity | 4 | Цели проверок четко сформулированы, но некоторые пункты могут быть более детализированы для улучшения понимания. |
| scenario_coverage | 5 | Проверки охватывают все необходимые позитивные и негативные случаи согласно требованию. |
| unambiguity | 4 | Формулировки точны, но некоторые условия могут быть более конкретными для исключения двусмысленности. |
| atomicity | 5 | Каждый пункт документа описывает одну проверяемую вещь без дублирования. |
| singularity | 4 | Пункты уникальны, но можно добавить небольшое разделение для улучшения читаемости. |
| consistency | 5 | Все пункты документа согласованы и не противоречат друг другу. |
| correctness | 4 | Значения и условия совпадают с требованием, но некоторые формулировки могут быть более точными. |
