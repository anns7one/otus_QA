# Спецификация API: JSONPlaceholder

Базовый URL: `https://jsonplaceholder.typicode.com`

## Ресурсы

| Ресурс | Количество |
| `/posts` | 100 |
| `/comments` | 500 |
| `/albums` | 100 |
| `/photos` | 5000 |
| `/todos` | 200 |
| `/users` | 10 |

## Схема объекта Post

```json
{
  "userId": 1,
  "id": 1,
  "title": "строка",
  "body": "строка"
}
```

Поля: `id` и `userId` - целые числа, `title` и `body` - строки.

## Схема объекта Comment

```json
{
  "postId": 1,
  "id": 1,
  "name": "строка",
  "email": "строка",
  "body": "строка"
}
```

## Эндпоинты (коды ответов проверены)

| Метод | Путь | Код | Тело ответа |
|---|---|---|---|
| GET | `/posts` | 200 | массив из 100 объектов Post |
| GET | `/posts/1` | 200 | один объект Post |
| GET | `/posts/999` | **404** | пустой объект `{}` |
| GET | `/posts?userId=1` | 200 | массив из 10 объектов Post |
| GET | `/posts/1/comments` | 200 | массив из 5 объектов Comment |
| GET | `/users` | 200 | массив из 10 объектов User |
| POST | `/posts` | **201** | созданный объект с полем `id` |
| PUT | `/posts/1` | 200 | обновлённый объект |
| PATCH | `/posts/1` | 200 | объект с применённым изменением |
| DELETE | `/posts/1` | **200** | пустой объект `{}` |

## Вложенные маршруты

Поддерживается один уровень вложенности:

- `/posts/1/comments`
- `/albums/1/photos`
- `/users/1/albums`
- `/users/1/todos`
- `/users/1/posts`

## Фильтрация

Через query-параметры: `/posts?userId=1`, `/comments?postId=1`.

## КРИТИЧНО: запись данных подделывается

> Сервис **не сохраняет** изменения. POST, PUT, PATCH и DELETE возвращают
> правдоподобный ответ, но данные на сервере не меняются.

Что это значит для тестов:

- `POST /posts` вернёт `id: 101`, но `GET /posts/101` после этого даст **404**;
- `PUT /posts/1` вернёт изменённый объект, но `GET /posts/1` вернёт исходный;
- `DELETE /posts/1` вернёт 200, но пост останется на месте.

**Поэтому проверять нужно контракт, а не сохранение данных:** код ответа,
структуру и содержимое тела ответа. Тест вида «создали → запросили →
проверили, что сохранилось» **упадёт**, и это не баг сервиса.

## Особенности, на которых легко ошибиться

1. `DELETE` возвращает **200**, а не привычные 204 No Content.
2. У объекта Post ровно **4** поля — нет ни `createdAt`, ни `updatedAt`.
3. `POST /posts` всегда возвращает `id: 101` — счётчик не увеличивается.
4. Авторизация не требуется, заголовки токенов не нужны.
