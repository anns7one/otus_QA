# Промпт для генерации API-автотестов

Построен по схеме **Роль → Контекст → Задача → Формат** (Тема 5 курса).
Используется скриптом `generate_tests.py`: часть «Контекст» подставляется
из файла `api_spec.md`.

---

## Роль

```
Ты senior AQA-инженер. Пишешь API-автотесты на Python 3 + pytest + requests.
Отвечаешь только кодом, без объяснений и без markdown-обёрток.
```

## Контекст

```
Спецификация тестируемого API:
{сюда подставляется содержимое api_spec.md}
```

Плюс образец теста — чтобы модель повторила стиль, а не изобретала свой:

```python
def test_get_single_post_returns_expected_schema():
    """GET /posts/1 возвращает объект с четырьмя полями."""
    response = requests.get(f"{BASE_URL}/posts/1", timeout=10)

    assert response.status_code == 200
    body = response.json()
    assert set(body.keys()) == {"userId", "id", "title", "body"}
    assert body["id"] == 1
    assert isinstance(body["title"], str)
```

## Задача

```
Напиши РОВНО 3 теста для API JSONPlaceholder:

1. test_get_posts_list_returns_100_items
   GET /posts возвращает 200 и массив ровно из 100 постов,
   у каждого элемента есть все четыре поля схемы Post.

2. test_create_post_returns_201_and_echoes_body
   POST /posts с телом {"title": "...", "body": "...", "userId": 1}
   возвращает 201, в ответе есть поле id, а переданные значения
   title, body и userId возвращаются без изменений.

3. test_get_nonexistent_post_returns_404
   GET /posts/999 возвращает 404 — негативная проверка.
```

## Формат

```
- один файл с тестами, готовый к запуску командой pytest;
- вверху: import requests, import pytest, константа BASE_URL;
- имена тестов — ровно как указано в задаче;
- каждый тест с docstring на русском в одну строку;
- в каждом запросе указывай timeout=10;
- никакого текста до и после кода, только сам код.
```

## Ограничения

```
- Используй ТОЛЬКО поля, коды ответов и эндпоинты из спецификации.
  Ничего не выдумывай: полей createdAt и updatedAt в схеме нет.
- Сервис ПОДДЕЛЫВАЕТ запись данных. Не пиши тестов вида
  «создал ресурс → запросил его → проверил, что сохранился»:
  такой тест упадёт, и это не будет багом сервиса.
  Проверяй контракт: код ответа, структуру и содержимое тела ответа.
- Не используй фикстуры и conftest.py — всё в одном файле.
- Не добавляй тесты сверх трёх перечисленных.
```
